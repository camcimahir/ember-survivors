# Ember Survivors

A mobile top-down survival shooter in the vein of *Survivor.io* / *20 Minutes Till Dawn*:
one thumb, endless waves, and a build that comes together out of three elements.

Everything in this repository — the code, the art, the sound, the icons — is
generated from source. There are no binary assets checked in.

---

## The hook: three elements, fifteen fusions

You may hold **at most three elements** for a whole run. Once the third slot is
filled, no new element card will ever appear again — every later pick deepens
what you already chose.

| Element | Weapon | Signature status |
|---|---|---|
| **Ember** (fire) | Cinder Bolt — bursting fireballs | Burn (damage over time) |
| **Volt** (storm) | Arc Coil — chain lightning | Shock (stun + conducts) |
| **Rime** (frost) | Rime Nova — expanding frost ring | Chill / Soak / Freeze |
| **Bloom** (verdant) | Thornseed — seeking spores | Poison + Root |
| **Edge** (steel) | Buzzsaw — orbiting sawblades | Shatter (vs. frozen) |
| **Rift** (void) | Singularity — a rift that pulls | Mark (amplifies damage) |

Get **any two of your elements to level 3** and their **fusion** appears as a
gold card: a brand-new weapon that is not a stat boost but its own behaviour.
All fifteen pairs exist.

| | Ember | Volt | Rime | Bloom | Edge |
|---|---|---|---|---|---|
| **Volt** | Plasma Storm | | | | |
| **Rime** | Steam Burst | Cryo Conductor | | | |
| **Bloom** | Wildfire | Lightning Rod | Permafrost Bloom | | |
| **Edge** | Molten Saw | Railgun | Glacier Chakram | Bramble Cutter | |
| **Rift** | Supernova | Tesla Rift | Absolute Zero | Devourer | Gravity Blades |

Elements also combine *passively*, through status interactions resolved on every
hit, so cross-element builds pay off even before you fuse:

- **Storm into wet or chilled** targets deals **+50%** — frost sets up storm.
- **Fire into wet** flashes to steam: **+35%** and the soak is consumed.
- **Steel into frozen** shatters for **+100%** — frost sets up steel.
- **Fire into frozen** thaws the target for **+30%**.
- **Verdant into marked** feeds for **+20%** — void sets up verdant.

### Enemies

Crawler, Runner, Spitter (ranged), Dasher (telegraphed charge), Bomber
(explodes, and hurts its own side), Brute (tanky, knockback-resistant), Splitter
(breaks into two), Wraith (phases through the crowd), Bulwark (blocks 55% from
the front — flank it), and a **Warden** boss every couple of minutes that slams,
summons escorts, and drops a treasure chest.

## How the art is made

The art is **procedural vector code**, rasterised once into offscreen canvases
at startup and blitted thereafter (`src/engine/sprites.ts`).

This is the right approach for LLM-authored art. Rather than describing an image
and hoping, every curve is stated exactly and can be reasoned about and revised:

- **`src/art/style.ts`** — the style tokens. Palette ramps, outline width as a
  fraction of sprite size, light direction. One file restyles the whole game.
- **`src/art/draw.ts`** — the shape language: `blobPath`, `flamePath`, `sawPath`,
  `boltPath`, `shardPath`, `eyes`, `fangs`, `glow`, and the `shaded()` routine
  that applies the house style (bold outline → top-lit gradient → one specular).
- **`src/art/actors.ts` / `fx.ts` / `icons.ts` / `env.ts` / `logo.ts`** — every
  sprite, composed from those primitives.

Consequences: the whole game is **~42 KB gzipped**, art is resolution-independent
(rasterised at device pixel ratio), and a palette change propagates everywhere.

Animation is code-driven too — squash/stretch, bob, lean, hit-flash and status
tints are applied at draw time, so each creature needs only one sprite.

**Audio** follows the same principle: every sound is synthesised from
oscillators and filtered noise at runtime (`src/engine/audio.ts`), plus a small
generative music loop whose intensity tracks how dangerous the field is.

**Icons** are generated by `tools/gen_icons.py` (Pillow) — launcher icons at
every density, adaptive-icon layers, splash screens, and the Play Store icon and
feature graphic.

## Running it

```bash
npm install
npm run dev
```

Open the URL it prints. Drag anywhere to move — a floating stick appears under
your thumb; aiming and firing are automatic. WASD/arrows work on desktop.

### Testing on a phone

The dev server binds to all interfaces, so any device on the same network can
open `http://<your-lan-ip>:5173`. To get a scannable link:

```bash
python tools/gen_qr.py
```

That detects your LAN address and writes `store/dev-qr.png`. Pass a port to
point it at the production preview instead: `python tools/gen_qr.py 4173`.

The QR encodes the scheme explicitly as `http://`. That matters: a bare
`host:port` typed into Chrome's address bar gets upgraded to HTTPS, and the dev
server speaks plain HTTP, so you get *"this site can't provide a secure
connection"*. If it still happens, turn off **Settings → Privacy and security →
Security → Always use secure connections** in Chrome. Nothing in the game needs
a secure context — there is no service worker, geolocation or camera use, and
WebAudio works fine over HTTP.

Once it loads, use Chrome's **Add to Home Screen** and launch from that icon —
the page declares `mobile-web-app-capable`, so it opens fullscreen with no
browser chrome.

Other scripts:

```bash
npm run typecheck
```

```bash
npm run build
```

```bash
npm run icons
```

## Building the Android app

The `android/` project is committed and configured (portrait-locked, adaptive
icons, splash, release signing wired up). Building an installable artifact needs
a JDK 17+ and the Android SDK, which are **not** required for anything above.

Install [Android Studio](https://developer.android.com/studio), then:

```bash
npm run build && npx cap sync android
```

```bash
npx cap open android
```

From Android Studio you can run on a device/emulator directly. To produce an
upload artifact from the command line instead:

### 1. Create a signing key (once — keep it forever)

```bash
keytool -genkey -v -keystore android/ember-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias ember
```

### 2. Point Gradle at it

```bash
cp android/keystore.properties.example android/keystore.properties
```

Edit `android/keystore.properties` with your passwords. It is gitignored, as is
the `.jks` itself — neither is ever committed.

### 3. Build the App Bundle

```bash
cd android && ./gradlew bundleRelease
```

The upload artifact lands at
`android/app/build/outputs/bundle/release/app-release.aab`.

### 4. Publish

In the [Play Console](https://play.google.com/console), create the app and
upload that `.aab`. Store assets are pre-generated in `store/`:

- `play-store-icon-512.png` — the 512×512 listing icon
- `feature-graphic-1024x500.png` — the feature graphic
- Screenshots: run the game and capture a few (Play requires at least two)

You will also need a privacy policy URL, a content rating questionnaire, and a
Data Safety declaration. This game collects nothing, has no network calls, no
analytics, and no ads — all three are quick to fill in.

### iOS

`capacitor.config.ts` includes iOS settings and `npx cap add ios` will scaffold
the project, but iOS requires macOS + Xcode, so it is **untested here**. Android
is the supported target.

## Architecture

```
src/
  engine/     framework-free: loop, pooling, spatial hash, input, audio, sprites
  art/        every sprite, drawn in code
  game/       the simulation
    content/  data: mobs, the 6 elements, the 15 fusions, passives
  ui/         DOM overlay (HUD, cards, menus)
```

Design notes worth knowing before changing things:

- **Fixed timestep.** The sim always advances in exact 1/60s steps
  (`engine/loop.ts`) so pacing is identical on 60/90/120 Hz panels. Rendering is
  decoupled and runs once per animation frame.
- **Nothing allocates in the hot loop.** Enemies, bullets, particles, pickups and
  zones all live in fixed-capacity pools (`engine/pool.ts`) with swap-remove.
  GC pauses are the main source of stutter on mid-range Android.
- **One weapon framework, 21 weapons.** Every weapon is a `WeaponDef`
  (`game/weapons.ts`) composing attack primitives that live on `World` —
  `shoot`, `explode`, `nova`, `chain`, `beam`, `zone`, plus orbital bullets.
  Adding a weapon is a data change.
- **All damage flows through `World.damageEnemy`,** which is where the elemental
  interactions, armour, crits and lifesteal resolve — so every weapon gets them.
- **Canvas for gameplay, DOM for text.** Crisp typography at any DPR and real
  layout for the card screen, at no runtime cost.

### Measured behaviour

Driving the simulation headlessly (`window.__game`, see below):

- 10 minutes of simulated play: **worst sim step 0.25 ms** against a 16.6 ms
  budget, with 420 enemies, ~900 particles and 8,000+ kills. No NaN, no leaks.
- All 15 fusions verified to gate correctly (0 leaks below the level-3
  requirement, exactly the right fusion at it) and to deal damage when fired.
- The 3-element lock verified across 1,800 card offers: no fourth element ever
  appears.

### Debug API

`window.__game` is exposed for testing and is not used by gameplay:

```js
__game.addElement('fire', 5)      // grant an element at a level
__game.addFusion('plasma', 3)     // grant a fusion
__game.spawn('brute', 10, true)   // spawn mobs (kind, count, elite)
__game.roll(3)                    // roll a hand of upgrade cards
__game.pick(card)                 // apply one
__game.step(600)                  // advance 600 fixed steps
__game.renderFrame()              // force a render
__game.godMode(true)
__game.listWeapons()
```

## Tuning

Balance lives in a few places, all plain numbers:

- `src/game/content/mobs.ts` — per-mob HP, speed, damage, XP, spawn weight and
  unlock time.
- `src/game/world.ts` — `xpForLevel()`, the spawn-rate ramp and the enemy HP/damage
  curves in `spawnEnemy()`.
- `src/game/content/elements.ts` / `fusions.ts` — per-weapon damage and cooldowns.
- `src/game/types.ts` — `baseStats()`, the player's starting numbers.
- `src/game/render.ts` — `DESIGN_VIEW_WIDTH`, how many world units are visible
  across the screen. Zoom is derived from it, so a phone and a tablet see the
  same amount of arena rather than the tablet getting a free advantage. Larger
  values zoom out: 480 is tight, 540 is the default, 620 is wide.

The player always keeps a weak **Sidearm** that costs no element slot, so a run
can never dead-end with no way to deal damage.
